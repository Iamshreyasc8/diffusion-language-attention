# Diffusion Language Attention

**Where does a text-to-image model attend when it interprets a phrase?**

A research project using Stable Diffusion and DAAM to visualize word-level attention and compare spatial overlap within multi-word expressions. The maintained workflow takes a prompt and expression, generates an image, extracts word heatmaps, and exports overlap scores with run metadata.

## Quick start: analysis only

Use Python 3.10–3.12 for analysis (Python 3.11 is the shared choice for the model stack). Clone the repository, enter its folder, and create a virtual environment:

```bash
git clone https://github.com/Iamshreyasc8/diffusion-language-attention.git
cd diffusion-language-attention
python -m venv .venv
```

Activate with `source .venv/bin/activate` on macOS/Linux, or `.venv\Scripts\Activate.ps1` in Windows PowerShell. Then:

```bash
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
```

No Hugging Face account, GPU, or model download is needed for these tests. To open the walkthrough:

```bash
python -m pip install -r requirements-notebook.txt
python -m jupyter lab notebooks/01_attention_demo.ipynb
```

## Generate real images and attention maps

Use a **separate Python 3.10/3.11 environment** for the legacy DAAM model stack. The dependency file follows DAAM 0.2.0's pinned Diffusers, Transformers, and Accelerate versions. The CUDA lockfile targets Linux with Python 3.11 and has been dependency-resolved. A separate CPU lockfile has passed real-library integration tests with random weights; full pretrained inference remains unverified. On other platforms resolve `requirements-model.txt` with the appropriate PyTorch wheels. See [validation status](docs/validation.md).

```bash
python -m pip install -r requirements-model.lock.txt
python -m pip check
```

For the tested Linux CPU profile, use `requirements-model-cpu.lock.txt` instead of the CUDA lockfile.

For the notebook, also install `requirements-notebook.txt` in that environment and select its kernel. If model access requires authentication, run `huggingface-cli login` or configure `HF_TOKEN` locally. Never put access tokens in notebooks. Model weights download on first use; allow several GB of disk and adequate RAM/VRAM.

From the repository root:

```bash
python -m diffusion_attention.demo --prompt "A red fire truck parked on a quiet street" --expression "fire truck" --seed 42 --steps 20 --output outputs/fire-truck
```

Or process the included CSV:

```bash
python -m diffusion_attention.demo --csv examples/prompts.csv --seed 42 --output outputs/examples
```

Options include `--device auto|cuda|cpu`, `--model`, `--revision` (model commit SHA), and `--percentile`. `auto` selects CUDA when available and otherwise CPU; CPU runs in float32 and can be very slow. Apple MPS is not implemented. The full demo uses 512×512 images and guidance scale 7.5. The model safety checker stays enabled.

The default model is [`stable-diffusion-v1-5/stable-diffusion-v1-5`](https://huggingface.co/stable-diffusion-v1-5/stable-diffusion-v1-5); access and license terms are governed by its publisher. This model choice differs from the historical SD2 example. The sample CSV is a demonstration set, not an evaluation benchmark.

Each run saves:

- `generated.png`: generated image.
- `attention.png`: normalized overlays and binary masks.
- `heatmaps.npz`: raw word-level arrays.
- `scores.json`: pairwise scores, missing words, seed, model, scheduler, device, and package versions.

Existing output directories are never overwritten. CSV outputs use numbered subdirectories and stop on generation errors; earlier completed rows remain on disk. If a run fails after creating its output directory, choose a fresh path for the next attempt.

## What the score means

For nonnegative heatmaps A and B:

`continuous IoU = sum(min(A, B)) / sum(max(A, B))`

A score of 0 indicates no shared mass; 1 means equal nonzero heatmaps. Two zero maps return 0 by convention. Scores use raw amplitudes, so relative intensity matters; they are not computed from the display-normalized overlays or binary masks.

- Zero and uniform maps produce empty masks: no localized region is distinguishable.
- Missing word maps are reported and excluded from pairs, not converted into fake zeros.
- Repeated word occurrences are aggregated by DAAM; the wrapper deduplicates expression words.
- Prompts exceeding the model's token budget are rejected before inference.
- Seeds and versions are recorded, but bitwise identity across hardware is not guaranteed. Supply a model commit SHA with `--revision` for stronger reproducibility.

Attention overlap is an exploratory signal. It does not establish semantic understanding, compositionality, or linguistic correctness. The repository does not claim benchmark accuracy or quantitative research findings beyond its tested numerical examples.

## Research scope and next evidence

The original notebooks explore prompt preparation, token counts, word/head attribution, and multi-word-expression overlap. The maintained code focuses on a reproducible attribution-and-overlap workflow. Before using scores as research evidence, run the full model demo, record the environment and model revision, and evaluate several prompts and seeds against a defined hypothesis or labeled dataset.
